# Learnings Folder

This folder contains documented findings from feasibility studies, proofs of concept, and probing experiments.

## Naming Convention
`XXX-finding-descriptive-name.md` — three-digit sequential numbering shared across `plans/`, `probing/`, `poc/`, `fixtures/`, `learnings/`.

## Template
Each learning document should include:
1. **Date** — when the study concluded
2. **Study Context** — what was being evaluated and why
3. **Summary** — one-line conclusion
4. **Key Findings** — detailed evidence, organized by topic
5. **Recommendation** — go/no-go with rationale
6. **Next Steps** — concrete actions (new probing, PoC, plan updates)
7. **References** — links to sources, PRs, docs, code

## Current Learnings

- [001 — Ground-Truth Dataset Feasibility & Source Survey](001-ground-truth-dataset-feasibility.md) — Schema is 49 fields (not 52); no drop-in Indic PDF+metadata dataset; build from Wikidata/Commons/Wikisource + s1.md seed + manual verification (CC/PD-only). Metrics, split, and phased PoC proposed.
- [005 — LLM Model Evaluation for Metadata Extraction](005-llm-model-evaluation.md) — Resource/speed arm measured on the 4 vCPU/16 GB node: `qwen3:4b-instruct-2507` is the safest drop-in (valid JSON, ~½ RAM, ~1.6× the 7B baseline); `qwen3.5:4b` fastest only with `think:false` (default returns empty). Accuracy arm pending GT verification.
- [002 — GT Enrichment from Wikisource + Internet Archive](002-gt-enrichment-sources.md) — Grew GT to 14 books (9 tel/5 hin), 4–11/49 fields each; te.wikisource Index header + IA metadata are the productive sources; hi.wikisource has no proofreading; remaining fields are genuinely absent.
- [003 — Harness Wiring + Scaling GT from Wikisource Index Pages](003-harness-and-wikisource-scaling.md) — 19 books (14 tel/5 hin), 14 with page-level OCR GT; harness `--ground-truth` mode scores the corpus (stub-validated; real run needs Ollama+Postgres).
- [004 — OCR-Stage Error vs Wikisource GT](004-ocr-stage-cer.md) — Measured Tesseract Telugu CER ≈ 0.45 median (range 0.20–0.62); OCR is the dominant error source. Also: `PDFService.render_pages` (used by the harness) does not exist.
- [006 — First Real End-to-End Accuracy](006-first-real-accuracy.md) — Harness run on GCP `test-node-3` (8 books, `qwen2.5:3b`): micro-F1 **0.308**; structured fields work, name/text fields precise but low-recall; `description_work` fails.
- [010 — LLM Shortlist Benchmark + Ollama RAM](010-llm-shortlist-benchmark.md) — 49-field sweep on 1 book: **phi4-mini F1 0.50** > qwen2.5:3b 0.31 > qwen3-4b-instruct-2507 / qwen2.5:7b 0.20; measured RAM 4B=3.38 GB, 7B=4.83 GiB. Fixed harness hardcoded-`tel` language bug.
- [007 — UI/UX Audit: Book Workflow + Admin Dashboard](007-ui-ux-workflow-admin-audit.md) — Full audit with verified file:line defects: five P0 data-integrity bugs (LLM-config trap, OCR editor state bleed, fake stepper, re-run OCR dead end, preprocessing config misuse), per-stage gaps, admin duplication; phased plan approved (see `plans/006`, `todos/008`).
- [008 — Auth/RBAC Implementation Outcome](008-auth-rbac-outcome.md) — Shipped cookie+CSRF sessions, rotating single-use refresh, owner-scoped enforcement, metadata-only public catalog, and admin user management on the existing stack (no pipeline changes); residual gaps: no per-user quotas, auth-only rate limits, SMTP dependency.
- [009 — Specialized Decision & Classification Models vs Generative LLMs](009-decision-classification-models.md) — Desk study + live probes of OpenRouter's Decisions/Extractions categories ($0.0006 spent). Decisions return typed judgments, not values — the alpha API 400s on any value-typed field; `choice`/`noul` classify Hindi/Telugu well (language survives p=0.45 corruption). Paid probe: clairic/ScaleDown extract Indic values from *text* (5/5, 4/5) but **neither reads a Telugu scan** — the OCR bypass is closed. Recommendation: keep the generative LLM as extractor; decision models only as a calibrated *validator* behind a measured gate.
- [011 — Deployment Exposure Audit & Single-Origin Fix](011-deployment-exposure-and-single-origin.md) — Prod was undeployable since the auth commit (two `:?` env vars missing from Dokploy → 404), and once up every mutation 403'd because the API sat on its own subdomain (host-only CSRF cookie unreadable by the frontend). Fixed by making the frontend host the single public entry point with the API at `/api`; audited and closed the rest of the exposure (backend, flower, Dokploy :3000, Traefik :8080).
- [012 — Moderated Signup, Admin-Only Library, Owner-Only Book Access](012-moderated-signup-outcome.md) — Shipped `plans/007`: additive `account_status` migration (backfills `approved`), a router-level `require_approved_user` gate (pending/rejected → 403, `/auth/*` stays open for the holding screen), admin approve/reject endpoints + pending-count badge, and removal of the public catalog (Library is admin-only; book detail/thumbnails are owner-or-admin, non-owner 404). No anonymous access.
- [013 — Verified-GT Shortlist, OCR Variant & Recall Diagnosis](013-verified-shortlist-and-ocr.md) — 35/35 books source-verified; on verified books **phi4-mini F1 0.333 ≫ qwen3-4b-instruct-2507 0.106** (confirms 010, contradicts 005); `tessdata_best` Telugu CER 0.419 vs 0.453 (marginal); recall failures = null-returns + a schema-echo bug (`title="CoreIdentityBatch"`); oki Ollama capped at 6 GiB.
- [014 — Frontend + Backend Route Redesign Outcome](014-routing-redesign-outcome.md) — Retired `/api/library/*` (catalog → `GET /api/admin/books` + `/api/admin/filters`; detail → `GET /api/books/{id}/detail`), grouped dashboard/job routes under `/api/dashboard` (cancel → `POST /api/dashboard/jobs/{id}/cancel`), and moved the bulk page `/bulk-operations` → `/admin/bulk`. The `/library` page was then removed (it duplicated `/admin/books`) and book detail moved to `/books/[bookId]`; verified on the oki host. Backend + frontend suites green.
- [015 — Service Inventory, Memory Profile & Non-Essential Gating (oki)](015-service-inventory-and-gating.md) — Non-essential services idle at **2522 MiB (16% of RAM)** — openrefine 1084 + elasticsearch 900 dominate — while a core-only stack runs at 1422 MiB. `COMPOSE_PROFILES` gating verified end to end with no restructuring (boolean `ENABLE_*` is not native to Compose, and runtime flags can't drive Next's build-time-inlined UI). Under load the pipeline peaks at 7713 MiB anon / 3070 MiB available, so **extraction wall-clock (81% of per-book vs OCR 19%) is the real constraint, not RAM**. Gating not yet implemented.
- [016 — The Pipeline Could Not Process a Book at HEAD](016-pipeline-non-functional-at-head.md) — Three layered defects made end-to-end processing impossible: stage tracking broken **five ways** (every transition raised), a preprocessing guard that matched the job that dispatched it (**OCR dead since 2026-09-01**), and an LLM persistence **self-deadlock** (KEY SHARE vs FOR UPDATE across two sessions) that hung silently at `running 100%` with zero rows written. All three fixed and verified to `awaiting_review`; 15+5 failing tests restored, 9 new stage tests added.
- [017 — Self-Hosted LLM Configuration: Parameter Reference & Evidence Base](017-llm-configuration-research.md) — Model/inference/runtime parameter reference with defaults, CPU/RAM impact and evidence. Measured calls are **0.9–1.4 K prompt + 53–70 output tokens**, so context is not the constraint — RAM residency, generated tokens and threads are. Provisional profile: `phi4-mini` or `gemma4:e4b` + `think:false`, Q4_K_M, ctx 4096–8192, **temp 0**, pinned seed, `num_predict` 512, `repeat_penalty` 1.0, 3 threads, 1 parallel, f16 KV, 6 GiB cap. Config conflicts found: ctx 8192 vs 4096, app parallel 2 vs server 1, max_tokens 256 vs 512.
- [018 — LLM Configuration Validation: Parameter Matrix on Verified Telugu Books](018-llm-config-validation.md) — 32-call matrix on `test-node-2`: **`gemma4:e4b` `think:false` F1 0.82/0.73 ≫ `phi4-mini` 0.35/0.44** (and phi4-mini **looped into invalid JSON** despite schema-constrained decoding). ctx 4096 ≡ 8192; temp 0 byte-identical across seeds; `repeat_penalty` 1.1 no help; 4 threads no help; **prompt-prefix caching ≈ 4× speedup**; no memory pressure (≥2.8 GiB free). Adopt **ctx 4096** + a repetition/loop guard.
- [019 — Enriching the Ground-Truth Corpus](019-gt-corpus-enrichment.md) — The empty fields were missing from the *sources*, not our extraction: added 14 CC/PD Hindi books (corpus → 30 tel / 19 hin), deepened catalog reads (Commons categories, IA subject/publisher, `ISBN` + Hindi Wikisource labels), and filled the scan-embedded fields with a node OCR+LLM pass. Coverage **308 → 623** non-null fields, **12 → 37 / 49** distinct fields populated; the fill run is 49 books in ~2 h. Key finding: `think:false` is ignored via the OpenAI-compatible endpoint (gemma4 returns empty content) and must use native `/api/chat`.
- [022 — Ground-Truth Source Expansion: scale, catalogue depth, script fix](022-gt-source-expansion.md) — Corpus **49 → 71 books** (+22 CC/PD Telugu/Hindi, 844 values). Catalogue adapters added little: Pustaka Nidhi matched 17 books whose titles were already Telugu; IA `dc.*` was already captured; the 22 new Commons-only books have **no IA id**, so identifier-keyed catalogues can't reach them. Script fix via free OpenRouter transliteration: Latin **author 26 → 11, title 11 → 8**. Page detector POC: `llm_text` ~5× more selective than a fixed window; the heuristic is useless on noisy OCR.
